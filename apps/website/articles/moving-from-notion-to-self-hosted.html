Moving from Notion to a self-hosted workspace

Export as Markdown, clean the file names, import as a vault, and know in advance what carries over and what you will rebuild by hand.

Leaving Notion is mostly waiting for an export to finish. This is the whole route from a Notion workspace to a self-hosted one, what comes across intact, and what you will fix by hand. It is written for Selfnote, but the first half applies to any tool that imports Markdown.

1. Export from Notion

In Notion, open Settings, then Workspace, then General, and choose Export all workspace content. Pick Markdown & CSV, include subpages, and start it. Notion emails a download link when the zip is ready, valid for a week; large workspaces take a while. Unzip it somewhere you can look at.

What you get is a folder tree. Every page is a Markdown file, every page with children is also a folder of the same name, and every file name ends with the page's Notion id, like Reading list 3f2a9c1b7d4e4a0c9b1e6f2d8c5a7b90.md. Databases become CSV files, one per database, plus a folder of Markdown files for their rows. Images and attachments sit next to the pages that use them.

2. Look at the export before importing it

Open a few files. Headings, todos, code blocks and tables are plain Markdown and will import as those blocks. Callouts are exported as HTML, which importers read as text. Links between pages are relative Markdown links with encoded spaces; most importers, Selfnote's included, do not resolve those. Decide now whether you want the databases: a CSV is a spreadsheet, not a page, and no page-based tool will turn it back into a board view.

If you want tidy titles, this is the moment to strip the id suffixes. On a Mac or Linux, from inside the export folder:

find . -depth -name '* [0-9a-f]*' -exec sh -c '
  for p; do
    n="$(dirname "$p")/$(basename "$p" | sed -E "s/ [0-9a-f]{32}//")"
    [ "$n" = "$p" ] || mv -n "$p" "$n"
  done
' sh {} +

The -n matters: if two pages shared a title, which Notion allowed and most tools do not, the second one keeps its id instead of overwriting the first. Spot check the result and rename those by hand.

3. Import into Selfnote

In the Selfnote web client, open the gear menu at the bottom of the sidebar and choose Import Obsidian vault, then pick the export folder. The importer treats it like an Obsidian vault:

  • folders become pages, nested the way the folders were nested,
  • each Markdown file becomes a page under its folder, with YAML frontmatter titles respected,
  • images referenced by the pages are uploaded and shown in place,
  • todos stay checkboxes, tables stay tables, code stays code,
  • wiki-style [[links]] are resolved to page links.

Three things a Notion export does that the importer does not yet handle, tracked in issue #115:

  • a Notion page with children is exported as both a file and a folder of the same name, so it arrives twice: an empty page holding the children and a page with the content beside it. Drag the children under the content page and delete the empty one, or leave the pair until the importer merges them,
  • Notion's links between pages arrive as links that point nowhere. Replace the ones you use with [[ links, which is step 5,
  • callouts arrive as their text, since Notion exports them as HTML.

CSV files are skipped. If a database matters, open its CSV in a spreadsheet and paste what you need into a table block, or keep the CSV as an attached file on a page.

4. Label everything

A big import lands as a tree with no labels. Labels are hidden until you switch them on with the Labels entry in the sidebar; once they are on, the import dialog also offers Label all notes (AI) if your server has an AI provider, which reads every page and tags it. Review the result page by page, since labels are easy to change. With no provider, labels are a few minutes with the picker on the pages that matter.

5. Rebuild the links that mattered

Notion's links arrived pointing nowhere, so search for pages that mention other pages by name and link them with [[. The backlinks panel then shows you the web you had in Notion, and the graph view shows the shape of it. This is the one part that is manual, and it is also the part that tells you which links you actually used.

6. Check you can leave again

Before you delete the Notion workspace, make sure the new home passes the test Notion just failed: take a backup of the Postgres database and keep it somewhere else. With Selfnote the database is the whole workspace, so a dump of it is a complete, restorable export, and the Helm chart does this on a schedule. Then close the Notion account, or leave it read only for a month; nobody has ever regretted the month.

What you gain

Your notes on a machine you control, offline editing that merges, no per-seat bill, an AI assistant whose provider you choose, and a database you can back up with one command. What you give up is in the honest comparison. If Selfnote is not the right shape, the same export works for the other self-hosted options.
