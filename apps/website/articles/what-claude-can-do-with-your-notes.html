What Claude can do with your notes over MCP

A tour of the thirteen tools the Selfnote MCP server gives Claude: search, read, propose edits, organise, and run your agenda, behind one revocable token.

Selfnote ships an MCP server, a small program that gives Claude a set of tools for your notes. Connect it once and every Claude you use, the command line, the desktop app or claude.ai, can act on your workspace from inside any conversation. This is a tour of the thirteen tools and what they are for.

Finding things

list_notes

The cheap browse. With no query it returns your recent notes; with one it matches titles. Each result carries the note's id and a link that opens it in the app, which is how Claude hands you back a clickable answer.

search_notes

Full text across titles, bodies and labels. "Find the note where I compared Postgres backup tools" is this tool. It uses the server's search index, so it is as fast as searching in the app.

get_note_links

The notes a page links to and the notes that link back to it. Claude uses it to follow your own structure before summarising or reorganising: if you ask for an overview of a project, it can walk the links instead of guessing which pages belong together.

list_workspaces

Only needed if your token can reach more than one workspace. Every other tool defaults to the first.

Reading and writing notes

read_note

Returns a note as Markdown. Claude is instructed to read before it edits, so a proposed change is based on what the page actually says. With a flag it returns the blocks with their ids, which is how a single checklist item becomes a task.

create_note

A new page, optionally nested under an existing one, optionally with a Markdown body. Markdown comes in as real blocks: headings, lists, checkboxes, code, tables, math.

save_conversation

The tool the whole project started from. Claude writes a summary of the current chat as Markdown, and this files it as a sub-page under a "Conversations" note, or under any note you name, and returns the link. The save-to-selfnote skill teaches Claude to summarise well and pick the right parent.

append_to_note and update_note

These two propose. Appending adds Markdown to the end of a page; updating replaces the whole body. Neither is applied: the server stages the change as a proposal, you see a before and after diff in the app, and you accept or reject. This is what makes it safe to say "add this to my feature ideas" from a chat on another device. Living documents goes into how the proposal pipeline works.

Organising

organize_note

Move a note under a different parent, rename it, change its icon, archive or trash it. These apply immediately, unlike body edits, because each one is undone with a single gesture in the app. There is deliberately no permanent delete: trash is as far as Claude can go.

manage_labels

List the workspace's labels, create one, read a note's labels, or add and remove them on a note. Add and remove are the safe operations and Claude prefers them; wholesale replacement exists for the case where you asked for exactly one set.

Tasks

manage_task and list_tasks

A note can be a task with a due date, status and priority, and so can a single block inside a note. These two tools create, update and list them, with filters for status, due window, parent note and labels. "What is overdue?", "what is due this week on the kitchen project?" and "mark the ferry booking done" are all one call. Your agenda from a chat has examples.

How access works

The server authenticates with a personal access token you mint in the app's Connections screen. It can do what your account can do, in the workspaces you belong to, and nothing else; the server enforces membership on every request exactly as it does for the clients. Revoke the token and every tool stops at once. For claude.ai the server runs as an HTTPS endpoint with its own bearer secret, one instance per user, so nobody else's Claude can reach your notes.

Why it is one process and not a plugin

MCP is an open protocol, so the same server works with every client that speaks it, now and later. It is also the reason this integration is deeper than any hosted notes app offers: the vendor of a hosted app has no incentive to let a third-party model read and write with this much freedom. On your own server there is no conflict, only the question of which door to open and how far. The MCP server is the door, the token is the key, and the proposals are the chain on it.

Setup takes five minutes: Claude and MCP. The server is published as @selfnote/mcp on npm.
