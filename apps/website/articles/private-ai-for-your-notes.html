Private AI for your notes: three ways to run it

Your Claude subscription running on your server, the Anthropic API, or Ollama on your own hardware. Same features, one difference that matters.

"AI note taking" usually means your notes go to someone else's model. It does not have to. Selfnote keeps AI off until the person running the server picks a provider, and three of them are supported. They differ in exactly one dimension that matters: where the text of your notes goes when you press the button.

Option 1: your Claude subscription, running on your server

The Selfnote API image bundles the Claude Code command line tool. You give the server a long lived token from claude setup-token, and from then on every AI request is handled by a process on your own machine, billed to the subscription you already have. The note text is piped to a local process and the answer comes back; no request to a Selfnote service, because there is none, and the Anthropic side sees only what the CLI sends, under the subscription's terms.

This is the recommended option because it combines the best model quality with the simplest privacy story and no new bill. Setup is three commands in the AI guide.

Option 2: an Anthropic API key

Set ANTHROPIC_API_KEY on the API deployment and the server calls the Claude API directly. The trade is explicit: the text of each request goes to Anthropic under their policy, and you pay per token. It is the lightest option to run and the right one when the server is small or the usage is occasional.

Option 3: Ollama on your own hardware

Point OLLAMA_HOST at a machine running Ollama and Selfnote uses whatever open weights model you have pulled. Nothing leaves your network. This is the option for a research notebook with unpublished material, for a clinic or a law practice, or simply for the person who has a GPU and would like it to earn its keep. Quality tracks the model you choose; recent open weights models summarise and rewrite well, and the "extract action items" action is well within reach of a small one.

What the AI can do, on any of the three

The provider is plumbing. The features are the same across it, and the same on web, desktop and mobile:

  • Assist chat that knows the note you are editing and, if you add them, the notes it links to and the ones you just visited.
  • Note actions: Summarize, Rewrite in my voice, Extract action items. One tap, streamed, insert or replace.
  • Labels: a bulk pass that suggests labels across a workspace, which is how an imported vault gets organised in an afternoon.
  • Proposals: every edit the AI wants to make to a note's body is staged with a diff for you to accept or reject. No provider gets to write directly.

What stays the same regardless

The clients show AI features only when the server reports a provider, so a plain instance has no dead buttons and no half-enabled features. The whole provider detection and dispatch is one Rust file you can read. And switching is a one line change: swap the secret, restart the deployment, and the same features run on a different model.

That last point is the real argument for self-hosting AI features rather than renting them. Models are improving monthly and the best one for your notes changes. When the provider is a setting on your server, you follow that curve. When it is a vendor's business decision, you wait.
