The clients

One editor, one sync core, three shells. Every client asks which Selfnote to talk to; no hardcoded servers anywhere.

Web

pnpm --filter @selfnote/web build     # → apps/web/dist (static SPA)

The browser client resolves its server from the page origin (/api for HTTP and wss://<host>/ws for sync), so a single build runs on any domain. Serve dist/ behind the reference nginx and you're done. Offline persistence is IndexedDB.

Desktop (Tauri)

cargo install tauri-cli --version "^2"      # once
cd apps/desktop && cargo tauri build        # native app + installer
cd apps/desktop && cargo tauri dev          # dev with hot reload

The desktop app bundles the web frontend in a Tauri 2 shell, about a tenth the size of an Electron equivalent. On first launch it asks which instance to connect to, since it has no serving origin of its own. Release bundles are unsigned unless you provide signing keys.

Mobile (Android / iOS)

Grab the Android APK from the download page, or build from source; the mobile app is a standalone Expo project with its own node_modules:

cd apps/mobile
npm install
npm run android         # or: npm run ios

On first launch the app asks for your server address (e.g. notes.example.com), derives /api and /ws, verifies the server, and saves it, changeable later in Settings. The editor runs the same BlockNote web editor in a WebView bridged to a native SQLite-backed Yjs store, so offline editing works the same as everywhere else.

All three clients share @selfnote/core: framework-free Yjs wiring, the sync client with reconnection and offline queueing, and a pluggable persistence interface. A feature added to the core lands on every platform.
