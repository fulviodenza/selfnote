Feature briefs

Each substantial feature starts as a written design brief in the repo — problem, data model, API, client behavior. The short versions:

Backlinks & graph view

Note-to-note links, a "notes that link here" panel, and a graph over the workspace — including an explorable 3D mode with an orbit camera. Because content lives in the CRDT rather than a queryable column, the client that owns the editor extracts outgoing links and reports them to the server. Full brief

Version history & time-travel

Named restore points along a timeline: browse, preview read-only, and restore any past state — implemented as a forward CRDT update that turns the current state back into the chosen one, so history is never destroyed and collaborators stay consistent. Full brief

Calendar & task sync

Any document can be promoted to a task with due date, status, and priority; tasks surface in an agenda view and publish as a read-only iCal feed for Google, Apple, or Outlook. A task is a document — no parallel entity. Full brief

Editor slash commands

Type / to insert tables, links to other notes, or run AI actions without leaving the keyboard — with strict parity across web, desktop, and mobile. Full brief

Diff-preview for AI edits

Any AI-originated write becomes a proposal — persisted but not applied, with a human-readable before/after — and turns into a real Yjs update only when a person accepts it. Especially important for remote MCP writes. Full brief

Note-level AI actions

Summarize, Rewrite in my voice (with a persisted per-user voice profile), and Extract action items — one tap on the current note or a selection, streaming a result you insert or replace. Full brief

Multi-note context for chat

The Assist chat can pull in linked and recently-viewed notes as extra grounding — chosen client-side, authorized and rendered server-side. Full brief

Share link analytics

Every public share link records views; owners see total views and last-viewed, so stale links get revoked with confidence. Full brief
