Claude & MCP

In a chat that has nothing to do with Selfnote, say "save this to my notes". Claude writes a clean summary into your instance and hands back the link.

How it connects

The Selfnote MCP server runs in two modes, built from the same package:

  • Local: a small stdio process next to Claude CLI or Claude Desktop.
  • Remote: an HTTP endpoint behind TLS, so claude.ai can reach it as a custom connector.

1. Mint a personal access token

In the Selfnote web app: Connections (sidebar) → name a token → Generate. Copy the snp_… value; it's shown once and can read and write your notes, so treat it like a password. Revoke it any time from the same screen.

2. Local setup (Claude CLI or Desktop)

cd tools/mcp-server && npm install && npm run build

claude mcp add selfnote \
  --env SELFNOTE_URL=https://notes.example.com \
  --env SELFNOTE_TOKEN=snp_... \
  -- node "$(pwd)/dist/index.js"

For Claude Desktop, add the equivalent entry to claude_desktop_config.json and restart; the selfnote tools should appear.

2b. Remote setup (claude.ai)

Run the server in HTTP mode behind TLS. On an existing cluster,, publishing a hostname through your Cloudflare tunnel is the easiest route:

docker run -d --name selfnote-mcp -p 8080:8080 \
  -e MCP_HTTP_PORT=8080 \
  -e MCP_HTTP_AUTH=$(openssl rand -hex 24) \
  -e SELFNOTE_URL=https://notes.example.com \
  -e SELFNOTE_TOKEN=snp_... \
  ghcr.io/fulviodenza/selfnote-mcp:latest

Then in claude.ai → Settings → Connectors → Add custom connector, point it at https://mcp.notes.example.com/mcp with the MCP_HTTP_AUTH value as the bearer token.

The server holds your token, so anyone who can reach /mcp acts as you. Always set MCP_HTTP_AUTH, stay on HTTPS, and run one server instance per user.

3. Teach Claude the workflow (optional)

The save-to-selfnote skill teaches Claude to summarize well, pick the right note, save, and report where it landed. Copy the folder into ~/.claude/skills/ (Claude Code) or your project's .claude/skills/.

What Claude can do once connected

  • save_conversation: file a Markdown summary of the current chat as a note and return its link.
  • list_notes: find the right note to target.
  • read_note, append_to_note, update_note: true in-place edits: the MCP reconstructs the Yjs doc, mutates it, and sends back an incremental CRDT diff. Edits merge cleanly and sync live to open editors, exactly like a human's keystrokes.

That last part makes "living documents" work: keep a running note and say "add X to my Feature Summary note": Claude finds it, reads it, appends, and it updates in place on every device.
