Architecture

One decision shapes everything else: real-time multiplayer and offline-first, together, mean the server can't resolve edits by timestamp.

Local-first + CRDT

Two clients can diverge — one offline for a day — and must merge without losing data or asking a human to pick a winner. That's a CRDT's job. Selfnote uses Yjs: the most battle-tested implementation, with native rich-text types, editor bindings, and a Rust port (yrs) that is wire-compatible — so JS clients and the Rust server speak the same protocol without reimplementing anything.

The consequence worth internalizing: a document is not rows in a table. Each page is a Yjs doc; Postgres stores metadata and the update log, not the block tree.

Two services, one clear split

clients (web / desktop / mobile — local-first, Yjs + IndexedDB/SQLite)
    │ WebSocket (Yjs sync protocol)          │ HTTP
    ▼                                        ▼
sync server (Rust, yrs)                 api server (Rust, axum)
  live rooms, presence,                   auth, workspaces, page tree,
  update relay + persistence              permissions, room tokens, AI
    │                                        │
    └────────────► Postgres ◄────────────────┘
         update log + snapshots + metadata
                    │
                    ▼
              MinIO (files, snapshot backups, WAL archive)
  • Sync server — the hot path. Holds live rooms in memory, relays CRDT updates, tracks awareness (cursors, presence), persists the stream. Rust/yrs keeps hundreds of rooms cheap.
  • API server — the control plane. Stateless and horizontally scalable. It decides who may open which room and issues short-lived room tokens (JWTs scoped to a document and permission) that the sync server verifies before admitting a WebSocket.

How a document is stored

  • doc_updates — an append-only log of Yjs updates (doc, sequence, author, bytes).
  • doc_snapshots — every N updates or T seconds the log is compacted into a snapshot and old updates pruned.
  • Loading a room replays latest snapshot + updates-since into yrs; snapshots are also pushed to MinIO for backup.
  • The page tree (nesting, titles, archive state) lives in normal Postgres tables, so navigation and search stay queryable; the block tree within a page lives in the Yjs doc, where merges happen.

The client stack

@selfnote/core is framework-free TypeScript shared by all clients: Yjs wiring, block operations, the sync client (reconnection, offline queue), a pluggable persistence adapter (IndexedDB on web, SQLite on mobile/desktop), and the API client. @selfnote/editor wraps BlockNote for collaborative editing. Desktop is Tauri 2 loading the same React bundle; mobile is Expo with the editor in a WebView bridged to native storage.

Why these languages

  • Rust for both servers: yrs is wire-compatible with Yjs and the sync path is memory-sensitive; axum keeps the API in the same language with types shared across services.
  • TypeScript for everything the user touches, with one shared core instead of three ports.
  • Go for the operator, where the kubebuilder ecosystem outweighs adding a third language to low-churn code.

Storage & backups

Postgres runs under CloudNativePG — HA, streaming replication, and continuous WAL archiving to MinIO with point-in-time recovery. MinIO also holds file uploads and versioned Yjs snapshots, so content is recoverable independently of the database. The restore path is a tested script (deploy/restore-drill.sh), not a hope.

The full design document, including the reasoning behind each trade-off, lives in the repo as ARCHITECTURE.md.
